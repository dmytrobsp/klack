# Fixes after v0.6.0 (queue V, part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Fix what the user found in v0.6.0 (2026-10-19): huddle invitations not arriving, Tab entering INSERT, redundant key hints in the huddle bar, the reaction picker's order, and dialogs that ignore mouse clicks.

**Architecture:** Each task is one small step in the existing code (crates/klack/src/tui/…); no new modules.

**Tech Stack:** Rust, ratatui 0.30, crossterm 0.29.

**Spec:** the user's report, quoted per task; for keys and modes, docs/superpowers/specs/2026-10-19-keymap-rework-design.md.

## Global Constraints

- The project's step routine: build without warnings, tests green, live check in the kitty test window, PROGRESS row (honest LIVE/UNIT/NOT, "(this commit)"), one commit with the `Co-Authored-By` trailer; the controller pushes after review.
- No `cargo fmt`; match the surrounding code; never touch target/release or the user's ~/.config/klack files without backup and restore; never capture the real microphone, camera or screen.
- DIALOG mode: a dialog owns all keys and clicks; a click outside it closes it (U1) — clicks INSIDE now act (Tasks 5, 6).

## Review Focus

- A click on a list row that the list has scrolled past (row index ≠ item index) — must pick the item drawn there.
- A click on the dialog's border, title or footer — does nothing.
- The huddle fix must not ring for your own huddle, for a muted conversation, or twice for one invitation.
- Tab with a thread open in a narrow terminal (the thread replaces the messages) — order still sane, never a composer.
- The reaction picker filtering by a query — your own reactions still marked inside the filtered list.
