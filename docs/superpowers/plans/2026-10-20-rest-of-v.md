# The rest of queue V Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close queue V. Add mute / unmute, mark unread, next unread conversation, copy a conversation's link and who
added which reaction. Re-test live that a huddle invitation rings outside Do Not Disturb.

**Architecture:** Each feature is a keymap `Action` (crates/klack/src/tui/keymap.rs, the `<leader> c` conversation group
and the sidebar context), handled in crates/klack/src/tui/event_loop.rs, with a Slack call in crates/slack-core/src/api.rs
where one is needed. Local state is in crates/klack/src/tui/state.rs (`Workspace`: `muted`, `unread`, …). Who reacted is
drawn in the reaction picker.

**Tech Stack:** Rust 2024, ratatui 0.30, crossterm 0.29. No new dependencies.

**Spec:** the user's words, recorded in PROGRESS.md "Next" → V (2026-10-19): "features that have no UI yet — mute /
unmute a conversation (`␣cM`), mark unread (`␣cu`), next unread conversation, copy a conversation's link"; "there is no
way to see who added which reaction (e.g. the picker's top lists the message's reactions with their people:
`👍 2 · you, alice`)"; and "a live re-test that a huddle invitation rings outside Do Not Disturb".

- Live checks run on the test workspace only: `--profile default` (A) or `--profile b` (B), never a bare `klack`. Use a

  ~/.claude/projects/-home-poniraq-projects-klack/memory/slacktui-live-test-gotchas.md). Anything a check changes on

## Review Focus

- Mark unread while the conversation is open: klack's own read-marking (on view / on scroll to the bottom) must not
  undo it at once. It stays unread until the user leaves the conversation and comes back, or reads on (a new
  selection below the mark). Test in Task 2.
- Muting the conversation that is open: the sidebar dims it and the unread count drops it, live, without a restart.
  Test in Task 1.
- Next unread with nothing unread, with only muted unread, or from inside a thread: a status note, no jump into a
  hidden or muted conversation. Test in Task 3.
- Who reacted, with many people or users not in the cache: the line is cut at the picker's width with "+N", and an
  unknown user shows their id's display fallback, never empty. Test in Task 5.

### Task 2 (V23): mark unread

**Files:** keymap.rs (new `MarkUnread`: `"mark_unread"`, "mark unread from the selected message (or the latest)",
`["<leader> c u"]`, plus `<leader> u` on a selected message in the messages view), event_loop.rs, state.rs.

Behaviour (Slack's "Mark unread"):
- With a message selected in the conversation (not in a thread), `conversations.mark` uses the ts just before that
  message: the previous message's ts, or that message's ts minus 0.000001 when it is the first one loaded. From the
  sidebar or with no selection, the mark is from the latest message.
- Locally: the conversation is unread (`has_unreads`), the "new" unread line sits above that message, and the sidebar
  shows it bold.
- klack's own read-marking is suspended for that conversation until the user switches away and back. Name the
  suppression, test it, and keep it with the conversation's state.
- Threads: in a thread view the action marks nothing and shows "mark unread works on the conversation's messages".

- [ ] **Step 1: failing tests.** `mark_unread_ts_is_just_before` covers the previous message, the first loaded message
  and the latest. `marking_unread_survives_the_view` covers the suppression: a draw or scroll-to-bottom does not call
  mark until the conversation is left and reopened.
- [ ] **Step 2: implement.**
- [ ] **Step 3: live.** A marks a message in the A–B DM unread. The sidebar row goes bold and the unread line appears.
  Switch away: it stays unread (check with a ctl `client.counts` read). Come back, and it is read again as normal.
- [ ] **Step 4: PROGRESS row, commit.**

### Task 3 (V24): next unread conversation

**Files:** keymap.rs (`NextUnread` `"next_unread"` "next unread conversation" `["alt+shift+down"]`, `PrevUnread`
`"previous_unread"` "previous unread conversation" `["alt+shift+up"]`, global like `NextConversation`), event_loop.rs,
state.rs (a pure `fn next_unread(&self, from: Option<&str>, down: bool) -> Option<String>` over the sidebar order).

- Sidebar order, wrapping round. Unread means the sidebar shows it unread (muted and hidden ones are skipped, the same
  rule as the status bar's count). Mentions are not ranked first: plain order, as Slack does.

### Task 5 (V26): who added which reaction

**Files:** the reaction picker (find it: `grep -rn "reaction picker\|ReactionPicker" crates/klack/src/tui`), plus
