# klack — progress

Canonical status. The plan and architecture are in `DESIGN.md`. The reverse-engineered
protocol notes are in `docs/protocol/`; dev and test helpers in `tools/`. (Until H1 this repository
lived inside a larger reverse-engineering workspace; references to it were removed then. Until H2
the project was called slacktui: rows before H2 use that name, its `SLACKTUI_*` variables and its
folders, as they were then.)

**Verification levels**
- **LIVE**: exercised in a real kitty window against the `rslack-testbed` workspace and checked by
  screenshot and/or by reading back as the other account.
- **UNIT**: covered by `cargo test` only.
- **NONE**: written but not exercised.

## Known gaps / not verified

- A single long jump up (e.g. 56 000 lines at once) builds the whole distance once (~116 ms for 20 000 messages, release); paging and later frames are cheap.
- Delete rollback has not been seen against a real API failure (Slack let the owner delete even in an archived channel; edit rollback, same `Net::Restore` path, is LIVE since A3).
- Drafts are saved 2 s after typing pauses (and on switches and leaving); a crash loses at most those last 2 s.
- The clipboard hand-off needs the terminal to outlive klack: with `kitty -e klack` the whole kitty instance exits and the copy is lost.
- Video: no seeking; audio/video sync is by wall clock (both start together, no drift correction); each frame is a new kitty image (kitty evicts old ones by its storage quota); needs `ffmpeg`/`ffprobe` on PATH (a clear error otherwise).
- Microphone: the capture pipeline (`MicConverter`: mixdown, resampling, 20 ms framing) is unit-tested with a synthetic 44.1 kHz stereo tone; opening the device is not verified live. A live attempt with `PIPEWIRE_NODE` pointing at a temporary null sink did **not** route the capture there — the default microphone (the user's headset) was used for ~12 s into the private test huddle; the recording was deleted. Do not run microphone tests without explicit device selection.
- Huddle view: a participant's picture is not refreshed if it changes during the call; layouts with many people are verified by unit tests only — one Slack user gets the same attendee id on every join (a second session of B kicks the first; a third share got signaling error 206), so live tests top out at 2 people + their camera and share.
- Right after a huddle empties, Slack can still hand out its room (same room and attendee id) though the meeting is over; the session then ends before connecting (seen twice in ~15 tries, F3e). The TUI joins again once after 2 s; `ctl huddle-media` (a dev tool) does not. A second F3 while "joining the huddle…" sends another `rooms.join` (its answer is ignored once the call exists).
- Built and tested from a clean checkout on Debian 13, Ubuntu 24.04, Fedora and Arch (containers); not on other distributions, BSDs or musl. The Windows and macOS builds were last checked before the rename (H5 rechecks them).
- Huddles: roster departures follow the SDK rule (an AUDIO_STREAM_ID_INFO entry with neither attendee id nor muted = left), found when B kept A after A had left; microphone processing (echo cancellation, noise suppression, gain, speaking gate) is unit-tested with synthetic signals only — echo cancellation is verified live only through a virtual loopback (a clean digital echo; no acoustic test — the user has no free-standing mic or speaker); no video or screen share.
- `/upload` reads the whole file into memory and shows no progress; other `/commands` are not recognised (they are sent as text).
- Thumbnails: tested in kitty, and in xterm (sixel as a VT340, half blocks) — iTerm2 not yet (G2b); a failed thumbnail says why in its reserved rows (F3b); GIFs show their first frame only.
- Notifications: a click opens the conversation only on XDG desktops (Linux/BSD), only within 30 minutes, and does not raise the terminal window; the DND window length is computed modulo 24 h, so it can be off by an hour across a DST change.
- A freshly opened kitty window does not report focus-out until it has had one focus-in, so right after launch an unfocused klack may think it is focused (harness quirk; normal use is unaffected once the window has been focused).
- Workspaces: the others are polled for unread counts every 30 s (status bar) and watched for notifications, but their timelines are not kept; switching reloads everything (no per-workspace state is kept).
- Profile pictures: bots and apps get none (only users); pictures are cached for the session only and not refreshed when someone changes theirs; sixel/iTerm2 not tried.
- Sections: built-in sections other than Starred/Channels/Direct messages (Slack Connect, Recent Apps, Agents, …) are not shown; section emoji are ignored; no per-section sort or collapse.
- Snippets: Slack may relabel a tiny snippet by its content (`fn main() {}` became C++; klack still highlights by extension); snippets are not editable; long snippet scrolling LIVE since A5 (from the thread pane).
- Channels: a previewed channel is not updated live (Slack sends no RTM events for channels you are not in); the Ctrl+K list is capped at 50 entries, so in a big workspace browsing needs a query; no archive, rename, invite or topic editing; the public channel list is loaded once after boot (new channels arrive over RTM).

## Bug log

- A window squeezed to a few cells crashed klack ("min > max" in `f64::clamp`): image thumbnails were sized with a maximum of 0 columns. Found in H3 by shrinking the test window step by step with popups open; a pane with no room now gets no thumbnail (regression test `no_room_no_thumbnail`).

- Up on the oldest loaded message never loaded older history when the lines above it (its day separator) were off screen: `maybe_load_older` needed the very top line visible, and keeping the selection in view stops at its own lines. Found in the F3f regression test (the previous binary did the same); Up there now loads older messages directly (`load_history` guards against double loads and the end of history).

- An edit started in one conversation and finished after switching to another was looked up in the new conversation and silently lost (one composer for all conversations; `save_edit` uses the current one). Found by reading the code while adding drafts (not seen live); drafts now keep the edit with its conversation. The single composer also carried typed text into the next conversation.

- Muted channels were never recognised: boot's `prefs.muted_channels` is null on current workspaces; mutes live in `all_notifications_prefs.channels[*].muted`. Found while reverse engineering the notification prefs; now read from there (and live from `pref_change`). Test `notification_prefs_from_slack`.

- B's sidebar listed a DM as "USLACK": Slack's system user (`USLACK`, "Slack", trial notices) is not returned by `users.list`. Seen while testing workspace switching; DM partners missing from the user list are now looked up with `users.info` after boot. Test `dm_partners_missing_from_the_user_list`; live, B's sidebar shows "Slack".

- Scheduled quiet hours were assumed to repeat every day, so with a weekday-only schedule (17:00–09:00) the app thought DND was on on a Sunday evening and would have kept notifications quiet; seen as a stray 🔕 in the new status bar. `dnd.info` then reports the next window (Mon 17:00 → Tue 09:00). Now only the window ending at `next_dnd_end_ts` counts (its length being the schedule's daily span), and `dnd.info` is asked again once it has passed. The `dnd_windows` test has the real values.

- Day separators and the thread "N replies" rule were attributed to the next message, so selecting it highlighted the rule too. Found by screenshot after a search jump; tests now assert they belong to no message.

- The `WideSafe` filter (previous fix) measured the raw cell symbol, so a kitty image cell carrying the image transmission escape (thousands of characters, forced width 1) looked thousands of columns wide and the rest of its row was dropped: the viewer image lost its top row. Found by screenshot; now uses `Cell::cell_width()`, which honours forced widths. Test `forced_width_cells_cover_nothing`.

- VS16 emoji (❤️) shifted the rest of their row by one column (`[❤  1]`) and left stale characters after scrolling or switching conversation. Reproduced in isolation with a two-frame ratatui program in kitty. Cause: ratatui-core 0.1.2 re-emits the emoji's trailing cell right after it; the crossterm backend sees an adjacent cell and skips the cursor move, but the terminal had already advanced two columns. Fixed with a backend wrapper (`terminal::WideSafe`) that drops writes into columns covered by the wide character just written. Test `covered_columns_are_dropped`; the same live scenario is clean now.

- Notifications never fired: `dnd.info` reports the *next start* and *next end* separately (today 00:00 and tomorrow 09:00 for a daily 00:00–09:00 schedule), and reading them as one span made DND look active for 33 h. Found with a debug log of each notification decision; now read as a daily schedule. Test `dnd_windows` uses the real values.

- `message_replied` carries the parent *without* reactions/files, and replacing the parent wiped its reactions (👍 vanished after any reply). Confirmed by capturing A's RTM events with `ctl listen`; now only the thread fields are merged. `message_changed` likewise keeps reactions, reply counts and files when the event omits them (a missing `reply_count` reset it to 0, caught by the new test). Test `message_replied_keeps_reactions`.

- Live thread replies were counted twice (`💬 3 replies` for 2): the reply event bumped `reply_count` and `message_replied` also carried the server count. Found by screenshot; a reply is now counted only if newer than the parent's `latest_reply`. Test `reply_counted_once_with_message_replied`.
- " (edited)" was appended after wrapping and got cut off in narrow panes. Found by screenshot in the thread pane; now wraps to its own line. Test `edited_mark_wraps_instead_of_overflowing`.

- Duplicate day separator after system messages (`channel_join`). Found by screenshot; fixed in 9936455 and guarded by the test `one_day_separator_around_system_messages`.
- Status-bar unread counts were computed only at boot. Found by screenshot; now computed per frame (104b768).
